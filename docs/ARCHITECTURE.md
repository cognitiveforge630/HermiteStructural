# Code architecture

## Design goals

The application has one modern `core/`, one canonical `tutorials/`, one `tests/` area that also hosts optional checks, and separate `studies/`/`tools/`. No active code is imported through old directories or shadow wrappers.

## Data flow

```text
PowerShell / VS Code task
        |
  tutorials.<order>
        |
  tutorials.cantilever
        |
  core.solvers.beam.build_beam
        |                    core.elements.<order>    core.materials.redwood
        |                      |
  core.elements.base      OrthotropicElasticity
        |
  core.mesh.structured
        |
  core.solvers.loads   --> integrated traction + gravity
        |
  core.solvers.constraints --> KKT face-displacement trace + prescribed rotations
        |
  core.solvers.linear  --> SciPy sparse solver (optional pypardiso backend in API)
        |
  core.solvers.results + core.reference.awc
        |
  outputs/<order>.json
        |
  core.visualization.sampling (direct Hermite interpolation and strain)
        |
  core.visualization.pyvista_viewer (3D contours, PNG, ParaView VTU)
```

`core/elements/base.py` still houses the Hermite basis, Jacobian, the common region object, and the orthotropic tensor class. The mesh functions are imported from `core/mesh/structured.py` to ensure all three variants use identical node ordering. Splitting the large base class further should follow verified regression tests, rather than risking geometry or interpolation changes merely for cosmetic modularity.

### Core elements

* `elements/linear.py`: `RecoveredRotationHex8` (one-ring, linear least-squares displacement-gradient recovery).
* `elements/quadratic.py`: `QuadraticRotationHex8` (two-ring quadratic recovery, mixed second derivatives).
* `elements/cubic.py`: `CubicRotationHex8` (three-ring cubic recovery with xyz mixed derivative, subject to grid rank).

These are six-DOF research methods. A recovered element draws on neighboring nodes beyond a single Hex8, so `element_transform()` and the shared global DOF stencil are essential; a conventional local-only 48×48 stiffness assembly would be incorrect.

### Solver boundary condition

`solve_with_face_dirichlet` uses a KKT system. Besides fixing the face nodal values, the method enforces sampled displacement traces generated by nonlocal recovery. The **current benchmark additionally fixes the face rotations** because the runner supplies zero rotations using the existing default. That is a modeling choice, not a proof that fixing spins is always appropriate for classical displacement Dirichlet conditions. Later comparisons should test `constrain_rotations=False` carefully and check rank, stability, and numerical convergence.

### Material and reference separation

`materials/redwood.py` contains the wood constants. `reference/beam_theory.py` and `reference/awc.py` compute independent classical cantilever comparison values, including weight per unit length. A displacement comparison does not modify, optimize, or calibrate any material constant.

### Test levels

Unit tests check modules and force resultants quickly. Standalone `tests.checks.*` add operator inspection and source-snapshot checks. Full benchmark solves are opt-in via tutorials because the bigger nonlocal stencils can become computationally expensive.

### Visualization data lineage

`sample_volume(beam,U,subdivisions)` evaluates the original element's
`element_transform` and `primitive_matrices` for displacement, and `primitive_B`
for strain/stress. The graphics grid subdivides each FE cell into purely
**display** cells. One-sided stresses are evaluated at all eight display-subcell
corners by default; the mean of those eight is retained only for cell coloring
(cell data), while raw corners are used for diagnostic extrema and error checks.
Displacement is reconstructed at shared visualization points (point data).
Changing subdivisions or displacement magnification does not refine or
re-solve the finite-element model.
